# 2026-09-02 — Scaffold, and the decisions worth making before any code

First session. The repository holds design documents and no implementation.

## Where this came from

A survey of AI-security tooling gaps across four domains — retrieval, agentic systems, model
supply chain, and evaluation methodology — produced one recurring shape. The ecosystem transcribes
claims and calls the result verification. Model signing attests bytes and says nothing about
lineage. AI-BOM generators read a model card and report what it asserts. Vector databases enforce
whatever tenant tag they were handed without asking whether it is true. Four machine-readable
agentic threat taxonomies now exist and none of them runs anything.

`whence` is the model-supply-chain instance of that gap, and it was selected first because it has
the least research risk: graph resolution, registry APIs, and schema conformance, with ground truth
available for nothing — published models with documented parentage are abundant.

## Decisions made, and why

Ten entries seeded in the decision log. Four of them are load-bearing and the rest follow from
them.

**Three-valued verdicts (DEC-001).** The temptation is a boolean with a confidence score, and it
fails the same way every time: a consumer reads a low-confidence `false` as `false`, and the third
state disappears at the first integration boundary. This is inherited directly from Trace's DEC-009
— a finding versus a documentation gap — and the reasoning transfers from controls to provenance
without modification.

**Digest pinning (DEC-002).** Unit 42's namespace-reuse work is the argument. A freed namespace can
be re-registered by anyone, and orphaned namespaces were reachable through two hyperscaler model
catalogs. A BOM that records names is recording assertions about the present, not facts about an
artifact.

**No model execution, ever (DEC-006).** This one is worth stating as a security property rather
than a limitation. `torch.load(weights_only=True)` was itself RCE-able through PyTorch 2.5.1;
Keras `safe_mode=True` had the same shape of bug; and `transformers` config deserialization
achieved arbitrary code execution with `trust_remote_code=False`. Every documented safe-loading
flag in this ecosystem has been bypassed. A provenance tool that must run the artifact to describe
it is a code-execution sink pointed at the population most likely to be hostile. Metadata and
structural headers only; anything requiring execution resolves `unverifiable`.

**Weight-level verification is deferred and its claim is bounded (DEC-005).** The published
fingerprinting methods are validated against models whose authors were not hiding anything.
Shipping that in phase one would gate the useful part behind the part with research risk, and would
invite a claim about adversarial laundering that the method does not support.

## The evaluation plan, and the file that makes it work

The truth-set layout splits expectations three ways rather than two, and that split is the whole
instrument. `expected-graph` scores recall. `expected-absent` scores invention. And
`expected-unresolvable` scores honesty: it holds edges that genuinely exist but cannot be
established from available metadata, so a tool that confidently resolves one is wrong even though
the edge is real. Without that third file, the correct behaviour under uncertainty is
indistinguishable from a miss, and there is no way to reward it.

The invention rate is a headline number rather than a footnote. A provenance tool that fabricates
plausible edges is worse than no tool, because it manufactures confidence in exactly the place an
operator has none of their own.

## Naming

`provenant`, the working name, is taken on PyPI by an active package published in August 2026 in
adjacent AI-tooling space — a collision worth avoiding rather than arguing with. `warrant` and
`attest`, the names for the two sibling projects, are also taken, both by packages abandoned over a
decade ago that PyPI will not release. Settled on `whence`, `tearline`, and `attestrun`, all free.
